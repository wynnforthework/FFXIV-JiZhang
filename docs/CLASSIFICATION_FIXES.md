# 分类修正 · 2026-10-31

## 已定位的代码缺口

- 聊天适配原先仅接收 SystemMessage、LootNotice、GatheringSystemMessage，漏掉 Progress、Notice、Urgent 等游戏系统通知频道。现在补齐该白名单，继续排除玩家聊天、Echo、雇员售出通知频道。读取未被其他插件改写的 OriginalMessage，而非最终显示文本。
- 普通“获得了1000金币。”原本可解析为系统奖励；挑战完成标题若单独发送，旧解析器不能保留来源。现在新增有时限、按角色隔离、一次消费的完成上下文，识别为“挑战笔记奖励”；中间的经验奖励不清掉上下文，其他无关系统通知会清掉。其他没有来源提示的金币奖励继续归为系统奖励。
- 传送适配仅拦截 Telepo.Teleport，遗漏 TeleportWithTickets 路径。现在分别尝试安装两个钩子；嵌套调用只捕获一次，费用和出发地在调用原函数前快照，原函数每次仅调用一次。
- 旧传送匹配在扣款两秒后即放弃，加载期间可能提前存成未分类。现在对待确认的真实余额变化最多等待90秒，抵达后以原始扣款时间匹配。账本按连续前缀写入，避免跳过待确认流水推进检查点。超时、退出和恢复操作仍会保存实际余额变化，无法确认时回退未分类。

## 不变的入账规则

只依据实际钱包余额变化生成账单；消息、请求和目的地本身不生成账单。金额不符、多个等额流水竞争证据、目的地冲突继续保留未分类；免费传送和取消请求不会凭请求产生账单。雇员出售只在实际提取金币进钱包时才能记入收入。没有历史证据的未分类流水不会被猜测性改写。

## 验证

单元测试包含用户提供的两条挑战消息、合并消息、经验奖励插入、全角金额、上下文过期/角色切换/无关通知、重复证据、未发生钱包变化，以及20秒加载、等候期间的连续流水与检查点、超时和退出保存。

本机 API15 构建通过不等于国服交易实测通过。本次未操作游戏完成传送或挑战奖励；需要重载新构建后验证新发生的交易。新增 Debug 日志只输出系统消息频道、解析分类、传送区域和预计费用，不记录聊天正文。
